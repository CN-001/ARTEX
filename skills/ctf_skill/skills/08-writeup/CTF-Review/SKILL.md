# ctf-review —— CTF 复盘专项 Skill

## 一、核心功能

| 职责 | 归属 |
|---|---|
| 题型识别、Session State、L1/L2/L3、假设状态 | **CTF-Analyzer-V2.0（大脑）** |
| 复盘框架、认知根源分析、可迁移清单、练习推荐 | **本 Skill** |
| 内容来源真实性判定 | **CTF-Analyzer-V2.0** |

本 Skill 不输出题型判断、不维护 Session State、不宣布 Level 等级。

## 二、核心理念

复盘的价值不在记录「做了什么」，而在提取**可迁移的思维模式**。

> 目标：让用户从「会这一道题」变成「以后遇到类似题知道怎么想」。

**复盘 = 认知根源 + 线索价值 + 假设证伪史 + 可复用清单。**

## 三、输入识别

| 输入类型 | 用途 |
|---|---|
| Session State 的 `Eliminated Hypotheses` | 错误尝试与证伪原因（**核心来源**） |
| Session State 的 `Confirmed Findings` | 正确思路与关键线索 |
| Session State 的 `User Attempts` | 实际走过的弯路 |
| 用户口述的卡点 | 认知根源分析 |
| 用户对题目的评价 | 难点定位 |

## 四、分析流程：复盘工作流

```text
「复盘」
    │
    ↓  1. 读取 Session State
    │      Eliminated Hypotheses / Confirmed Findings / User Attempts
    │
    ├── Session State 缺失或过旧 → 明确说明，请求用户补充卡点描述，不虚构
    │
    ↓  2. 认知根源分析
    │      「我一开始为什么没有想到？」
    │      → 定位到具体环节：不知道知识点？不知道该观察哪里？假设过早收敛？
    │
    ↓  3. 线索价值评估
    │      哪条 Evidence 是真正的转折点？为什么它当时被忽略了？
    │
    ↓  4. 假设证伪史梳理
    │      被淘汰的假设 → 为什么错 → 什么证据推翻了它
    │      （这是最有价值的部分：证伪能力比确认能力更稀缺）
    │
    ↓  5. 提炼可复用清单
    │      「下次遇到类似题先检查什么」——具体、可执行、不超过 5 条
    │
    ↓  6. 匹配练习
    │      基于本题知识点，推荐 2～3 个同类型练习方向或靶场
```

## 五、标准复盘模板

```markdown
# CTF 复盘

## 1. 我一开始为什么没有想到
（卡点的认知根源——是不知道知识点？还是不知道该观察哪里？
 还是假设过早收敛到单一方向？具体到环节，不要泛泛而谈）

## 2. 最关键的线索
（整道题的转折点在哪；这条线索为什么当时被忽略了）

## 3. 正确思路
（从线索到结论的完整推理链——一条线讲清楚）

## 4. 错误尝试
（实际走过的弯路——取自 Session State 的 Eliminated Hypotheses）

## 5. 为什么错误
（错误假设为什么站不住脚；什么证据本可以更早推翻它）

## 6. 本题知识点
（可迁移的技术与原理）

## 7. 下次遇到类似题目应该先检查什么
（可复用的检查清单——≤5 条，具体可执行）

## 8. 推荐练习
（2～3 个同类型练习方向或靶场）
```

## 六、输出格式

本 Skill 直接生成面向用户的完整复盘（产物是文档本身）。交付时：

- 在开头声明内容来源（基于 Session State / 用户口述）
- 缺失项明确标注（若 User Attempts 记录不全，第 4 节标注「记录不完整」而非虚构）
- 交付后主动询问「要不要把复盘整理进 Writeup 的第九节」

## 七、与 CTF-Analyzer-V2.0 的协作方式

```text
「复盘」
  → CTF-Analyzer-V2.0 读取 Session State
  → 调用 ctf-review
  → 本 Skill 读取 Eliminated Hypotheses / Confirmed Findings / User Attempts
  → 认知根源分析 → 证伪史梳理 → 可复用清单 → 练习推荐
  → 交付
```

**协作纪律：**

1. 本 Skill 依赖 Analyzer 的 Session State，不自行重建分析。
2. **禁止虚构错误尝试**——若记录不全，如实标注「记录不完整」。
3. **第 5 节（为什么错误）是复盘的核心**——证伪能力比确认能力更稀缺，重点写透。
4. 推荐练习必须与本题知识点同类型，不泛推「多刷题」。

## 八、安全边界

复盘内容仅限 CTF / 靶场 / 授权学习场景。不针对真实目标的攻击经历做「成功学」式总结。涉及真实目标的内容需脱敏后才能写入复盘。

## 九、自检规则

- [ ] 错误尝试是否全部来自 Eliminated Hypotheses / User Attempts？
- [ ] 是否编造了「我当时是这样想的」？
- [ ] 认知根源是否定位到了具体环节，而非「我不够细心」这类空话？
- [ ] 可复用清单是否 ≤5 条且具体可执行？
- [ ] 推荐练习是否与本题知识点同类型？
- [ ] 第 5 节是否讲透了「错误假设为什么站不住脚」？

## 十、与 Writeup-Generator 的关系

复盘是 Writeup 的第九节（复盘）的**独立深化版**。二者关系：

| | Writeup-Generator | CTF-Review |
|---|---|---|
| 产物 | 完整题解文档 | 认知提升文档 |
| 重点 | 「怎么解的」 | 「为什么没想到 / 学到了什么」 |
| 触发 | 「写 Writeup」 | 「复盘」 |

用户常在写完 Writeup 后说「复盘」，此时本 Skill 应**复用 Writeup 中已有的事实**，不重复分析。
