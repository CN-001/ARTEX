# 授权 / 合同 / 合规（接单必读）

## 0. 铁律

1. **没有书面授权，绝不测试**。口头允许不算。
2. 授权书必须写明：**测什么（范围）**、**什么时候（时间窗）**、**禁止什么（边界）**、**谁签署（授权人）**。
3. 客户数据**不进云端 API**——敏感项目切本地模型（见 `references/dual-model-policy.md`）。
4. 发现高危数据（用户库/密钥）→ 立即停止、只读取证、第一时间报告客户。

## 1. 接单流程（个人/小团队）

```
商谈需求 → 报价 → 签授权书 + 合同 + NDA → 实施（ARTEX 侦察+初筛，人工验证）
→ 出报告（报告草稿 + 人工复核） → 复测 → 归档
```

## 3. 合规红线（中国法）

| 法规 | 关键点 | 对你的约束 |
|---|---|---|
| 网络安全法 | 未经授权入侵=违法 | 只测授权范围 |
| 数据安全法 | 数据分类分级/出境管理 | 客户数据不出境（→ 本地模型） |
| 个人信息保护法 | 个人信息最小必要 | 不收集无关人员信息，社工演练需授权 |
| 刑法285/286条 | 非法侵入/破坏计算机信息系统 | 越界=刑事风险 |

## 4. 交付物标准

- 报告：封面（客户/项目/时间/授权编号）+ 摘要 + 测试范围 + 测试方法 + 漏洞清单（按等级）+ 详细漏洞（复现/证据/影响/修复建议）+ 附录（原始报文/工具清单）
- 复测报告：原漏洞修复状态（已修复/未修复/部分修复）+ 证据
- 归档：报告 + 授权书 + 原始证据（加密）

## 5. ARTEX 里的用法

- 创建任务时把授权信息写入任务描述（agent 会照做，越界可追溯）
- 敏感项目：任务模型切到本地 profile（`dual_model.ps1` 或界面设置）
- 报告：reporter agent 出草稿，**你人工复核**后交付

## 6. 常见坑

| 坑 | 后果 | 规避 |
|---|---|---|
| 只签授权书不签合同 | 收不到钱 | 合同+授权书都签 |
| 范围写"全公司" | 无权测内部系统 | 精确到域名/IP |
| 客户中途扩大范围 | 越界风险 | 补充授权书 |
| 报告夸大 | 客户反感/复测打脸 | 按实际写 |
| 口头承诺"包修" | 责任无限 | 写清交付边界 |
